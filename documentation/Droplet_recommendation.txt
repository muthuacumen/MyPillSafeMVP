  Guardrails — the price of co-tenancy done safely

  You accepted the blast-radius risk. Here's what neutralizes it (the first one is non-negotiable):

  1. Cap PillSafe with a cgroup memory limit. Run the brains sidecar (ideally the app backend too) in Docker with --memory=10g (or a systemd MemoryMax=).
  PathoIntern is already containerized/isolated; JAcI is bare-metal uvicorn as root with no limit — it's the exposed neighbor. A cap means if PillSafe
  balloons, the OOM killer takes PillSafe's cgroup, not JAcI's live site. This is what turns "could kill JAcI mid-demo" into "PillSafe degrades, neighbors
  survive."
  2. Pre-warm before you present. One throwaway pill scan + one throwaway Q&A minutes before → loads torch/paddle models and pages the 6 GB memmap into
  cache. Cold-start is where the ~2m21s CPU OCR and memmap paging bite.

  3. Confirm the app→sidecar timeout clears the OCR time (the proxy is httpx 180s; 2m21s fits, but verify — or use a pre-staged scan on stage).
  4. Bump swap to ~8 GB as an OOM backstop (safety net, not a place to run the memmap).
  5. Do the pending reboot + 27 apt updates (1 security) now, not near demo day. The report shows *** System restart required ***. A DO resize powers the
  droplet off anyway → fold the reboot into the resize, scheduled away from live JAcI traffic.

  Resize mechanics (and the cost-smart move)

  - Use "Resize CPU and RAM only" (reversible, keeps your 80 GB disk — which is fine, disk isn't the constraint). Avoid the permanent disk-grow resize; you
  don't need it.
  - Resize requires a brief power-off → short downtime for JAcI + PathoIntern. Schedule it.
  - DO bills hourly, and a capstone is a bounded event: scale up to 16 GB for the demo window, scale back to 4 GB after. The delta is only a few dollars a
  day (confirm current pricing in the DO panel). Reversible RAM-only resize makes this trivial.
  - The 16 GB tier also brings more vCPU, which helps the OCR latency (PaddleOCR threads) but won't erase it — that's still a design-around
  (pre-warm/stage), not a hardware fix.
